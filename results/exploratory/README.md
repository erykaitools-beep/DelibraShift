# Exploratory local-model checks

These files are deliberately separate from the frozen official M2 snapshot.
They are transport and screening evidence, not a leaderboard and not part of
the Build Week result claim.

## Repeated first-decision screen — 2026-07-19

`first_decision_repeated.json` is the auditable follow-up generated by
`tools/run_first_decision_smoke.py`. It uses the exact same rendered prompt for
both models and seeds 0, 1, and 2. Every raw response, raw-response hash, model
manifest digest, prompt hash, driver hash, parse flag, metric input, and Ollama
completion metadata is retained.

| model | valid replies | byte-identical raw | cycle-0 raw fidelity | position error |
|---|---:|---:|---:|---:|
| qwen2.5:3b | 3/3 | yes | 0.000022280 | 18.62 m |
| gemma3:4b | 3/3 | yes | 0.000743449 | 10.76 m |

Both transports produced parseable action and prediction objects without an
example echo in all three repetitions. Both were byte-identical across their
three seeds. Neither beats the cycle-0 persistence floor (`0.046801986`,
3.09 m position error). This is useful compatibility and determinism evidence,
but one scenario decision still cannot rank models or test the main M2 claim.

The recorded run used a dedicated Ollama server process on port 11435 so another
local application could not evict its models. The CPU host remained shared, so
wall-clock values are telemetry only. Reproduction on this host uses two
terminals:

```bash
OLLAMA_HOST=127.0.0.1:11435 \
OLLAMA_MODELS=/usr/share/ollama/.ollama/models \
OLLAMA_MAX_LOADED_MODELS=1 OLLAMA_NUM_PARALLEL=1 ollama serve
```

```bash
.venv/bin/python tools/run_first_decision_smoke.py \
  --model qwen2.5:3b --model gemma3:4b --repetitions 3 \
  --base-url http://127.0.0.1:11435 --dedicated-server \
  --output results/exploratory/first_decision_repeated.json --execute
```

## Initial pilot — partial evidence

`first_decision_smoke.json` is the initial pilot using END2END prompt `1.0` for cycle 0
of `g001` to locally installed Ollama models. Temperature is zero, seed is zero,
the response budget is 512 tokens, parsing uses the production harness, and
parse retries are disabled so one bad first reply is not hidden by repair.
The pilot did not retain its exact rendered prompt or driver, so it is marked
partial evidence; the tracked repeat driver below supersedes it for new runs.

| model | first reply | example echo | cycle-0 raw fidelity | position error |
|---|---|---:|---:|---:|
| qwen3:1.7b | parsed | yes | 0.000000001 | 56.91 m |
| qwen2.5:3b | parsed | no | 0.000025564 | 18.08 m |
| qwen3:8b | parsed | no | 0.046801986 | 3.09 m |
| llama3.1:8b | no balanced JSON | no | — | — |
| gemma3:4b | parsed | no | 0.000937232 | 10.20 m |

The persistence floor for this decision has raw fidelity `0.046801986`. Qwen3 8B
ties it exactly by returning the observed state unchanged. None of the tested
models beats the floor on this first decision. This single decision cannot
support an architecture or model ranking, and the raw per-cycle value is not
the official episode metric (which has a minimum-valid-cycle rule).

Wall-clock times are telemetry only: the host has no available GPU and its
Ollama service was shared with another process. Full exploratory runs must use
separate output directories, retain raw logs, use at least three repetitions,
and record whether Ollama thinking was enabled.

Ollama thinking is disabled for the recorded screening replies. The pilot also
recorded an unauditable Llama parse failure and an unauditable Qwen thinking-mode
observation; both are isolated under `unverifiable_observations` and are not
treated as results. See the [official Ollama thinking documentation](https://docs.ollama.com/capabilities/thinking).
